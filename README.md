# リプレイカメラ v0.5.2

[公開URL](https://azurewood-lab.github.io/replaycam/)

- 遅れて自動再生、または直前の動きを0.5倍で見返す。5・10・15・20・30秒、初期値10秒。再生位置バーで止めて見られる。描画・AI判定・比較表示・速度選択は追加しない。
- 遅延表示中の「この動きをスロー」は、実際に映っていたフレームを終点にする。「もどる」で撮影を再開。スロー中はカメラ停止。
- 「区間を選んで保存」を開くと、保持済みの最大30秒から同じバーと「ここから」「ここまで」で区間を選べる。撮影直後は実際にたまった分だけ。通常の見返しは選んだ秒数、保存画面だけ最大30秒へ広がる。遅延モードの保持区間は画面に映っていた時点までの30秒で、現時刻までの30秒とは異なる。
- 「動画を保存」は通常速度、「スローを保存」は0.5倍。任意操作でのみ動画ファイルを作る。MP4（H.264）を優先し、対応状況によりWebM（VP8）。形式は自動、音声なし。保存動画は撮影した向きで、表示の左右反転は含まない。スローは再生時間が約2倍、コマ補間なし。
- 映像は端末内で処理。音声収録・自動保存・アプリからの外部送信・共有・提出先連携は行わない。保存先やダウンロード許可はブラウザー・学校の設定による。保存したファイルは「おわる」で消えない。端末上に作るファイルと、アプリの一時映像は別。配信サービスのアクセス記録も動画送信とは別。
- 標準640×360・24fps目標、低め480×270・15fps目標。対応端末ではH.264 Highプロファイルと自動圧縮調整を使い、各フレームを最大保持時間と保存容量の枠に収める。調整できず容量を超える場合は停止し、低め画質への変更を案内する。カメラ入力や端末性能で下がる。高画質化は処理負荷を増やすため、学校の実機で確認する。他アプリと実写の見え方が同等以上とは未確認。
- 対応するネイティブコーデックで各フレームを独立して圧縮し、保持配列は64MiB以内。遅延時は選択秒数＋30秒＋0.8秒（最大60.8秒）、直接スロー時は30.8秒を上限にする。保存時の元データは32MiBまで、超過時は区間を短くする案内を出す。入力・デコード・描画・保存Blob・ブラウザー全体のメモリは保持配列とは別。保持量は実際の映像で変わる。
- VideoEncoder/VideoDecoderと必要な処理が使えない場合は従来の5・10・15秒へ戻る。動画保存と20・30秒は使えず、開始後にその旨を表示する。標準480×270・最大15fps（遅延15秒は10fps）、低め320×180・12fps。ArrayBuffer.transfer非対応の場合は従来のBitmap方式を使い、遅延からの見返しを隠す。
- 「おわる」、タブの非表示・離脱でカメラと一時映像を解放。停止後に操作のないまま60秒で一時映像を消去する。再生中は途中消去しない。連続撮影の上限は120分。ブラウザー自体が停止中の厳密な時限処理は保証しない。新方式の120分実時間検証は未実施。
- 学校のURL許可、カメラ許可、ダウンロード許可・保存先・保存ファイルの再生/提出先対応はそれぞれ別に確認する。学校Chromebook・実iPad・児童操作・実際の画質・発熱・電池は未確認。児童映像を開発用に収集しない。

HTML/CSS/JavaScriptのみ。外部ライブラリ・外部API・ビルド工程なし。ネイティブコーデック使用。ローカルはこのディレクトリで `python3 -m http.server 8765 --bind 127.0.0.1`。公開はHTTPSが必要。

この修正版は、同一の合成カメラ入力で細線・暗部・模様・動く輪郭と保存を比較して、細かい映像で保持時間が容量上限により短くなる問題を修正。画質/速度/保持/保存の選択肢は増やさない。フレーム通知が来ない場合は既存の描画更新を利用し、未更新フレームを再取得しない。比較はアプリ処理による劣化の試験であり、実カメラ・体育館照明・Chromebookの成功を意味しない。
